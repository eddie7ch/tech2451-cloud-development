Assessment Part 1 - Develop an API Endpoint
Commands used to provision and verify the coupons_list endpoint

1. Start LocalStack
-------------------
localstack start -d

2. Provision coupons_lambda_role (scripts/t1_provision_coupons_lambda_role.sh)
-------------------------------------------------------------------------------
awslocal iam get-role --role-name coupons_lambda_role
awslocal iam create-policy --policy-name coupons_lambda_role_policy --policy-document file://scripts/coupons_lambda_role_policy.json
awslocal iam create-role --role-name coupons_lambda_role --assume-role-policy-document file://scripts/coupons_lambda_role_assume_role_policy.json
awslocal iam attach-role-policy --role-name coupons_lambda_role --policy-arn arn:aws:iam::000000000000:policy/coupons_lambda_role_policy

3. Package and deploy the coupons_list Lambda (scripts/t1_provision_coupons_list_lambda.sh)
---------------------------------------------------------------------------------------------
npm install --prefix ./lambda/coupons_list
cd ./lambda/coupons_list
zip -r ../../coupons_list.zip .
cd ../..
awslocal iam get-role --role-name coupons_lambda_role --query Role.Arn --output text
awslocal lambda create-function --function-name coupons_list --runtime nodejs14.x --zip-file fileb://coupons_list.zip --handler index.handler --role <coupons_lambda_role ARN>

4. Provision the API endpoint (scripts/t1_provision_coupons_endpoint.sh)
---------------------------------------------------------------------------
awslocal apigateway get-rest-apis --query "items[?name=='coupons'].id" --output text
awslocal apigateway get-resources --rest-api-id <api id> --query "items[?path=='/'].id" --output text
awslocal apigateway create-resource --rest-api-id <api id> --parent-id <root resource id> --path-part coupons_poc
awslocal apigateway get-resources --rest-api-id <api id> --query "items[?path=='/coupons_poc'].id" --output text
awslocal apigateway put-method --rest-api-id <api id> --resource-id <coupons_poc resource id> --http-method GET --authorization-type NONE
awslocal lambda list-functions --query "Functions[?FunctionName=='coupons_list'].FunctionArn" --output text
awslocal apigateway put-integration --rest-api-id <api id> --resource-id <coupons_poc resource id> --http-method GET --type AWS_PROXY --integration-http-method POST --uri arn:aws:apigateway:us-east-1:lambda:path/2015-03-31/functions/<coupons_list lambda ARN>/invocations --passthrough-behavior WHEN_NO_MATCH
awslocal apigateway create-deployment --rest-api-id <api id> --stage-name local

5. Verify the endpoint
-----------------------
curl http://<api id>.execute-api.localhost.localstack.cloud:4566/local/coupons_poc
=> {"message":"Coupons API is working successfully"}

6. Run the unit test
----------------------
cd lambda/coupons_list
npx jest
=> PASS tests/index.spec.js - Coupon list > Should return success message

7. Run the Newman end-to-end test
------------------------------------
newman run newman_tests/coupons_newman.json --env-var "api_url=http://<api id>.execute-api.localhost.localstack.cloud:4566/local"
=> 2/2 assertions passed (Status code is 200, Response has success message)

Evidence of each step is captured under evidence/part1/:
- output.json            (live API response)
- unit_test_results.json (jest --json output)
- newman_report.json     (newman --reporter-json-export output)

Assessment Part 2 - Integrate Data Storage
Commands used to provision the coupons table/index and update the two Lambdas

1. Create the coupons DynamoDB table (scripts/t2_create_dynamodb_table.sh)
-----------------------------------------------------------------------------
awslocal dynamodb describe-table --table-name coupons
awslocal dynamodb create-table --table-name coupons \
  --attribute-definitions AttributeName=coupon_id,AttributeType=S \
  --key-schema AttributeName=coupon_id,KeyType=HASH \
  --provisioned-throughput ReadCapacityUnits=25,WriteCapacityUnits=10

(25 RCU: 50 eventually-consistent reads/sec / 2 reads-per-RCU = 25.
 10 WCU: 10 writes/sec x 1 WCU per ~1KB write = 10.)

2. Add the provider_id/campaign_id GSI (scripts/t2_add_index_to_dynamodb_table.sh)
---------------------------------------------------------------------------------------
awslocal dynamodb update-table --table-name coupons \
  --attribute-definitions AttributeName=provider_id,AttributeType=S AttributeName=campaign_id,AttributeType=S \
  --global-secondary-index-updates '[{"Create":{"IndexName":"provider_id-campaign_id-index","KeySchema":[{"AttributeName":"provider_id","KeyType":"HASH"},{"AttributeName":"campaign_id","KeyType":"RANGE"}],"Projection":{"ProjectionType":"ALL"},"ProvisionedThroughput":{"ReadCapacityUnits":25,"WriteCapacityUnits":10}}}]'

3. Update and redeploy coupons_get_by_id (scripts/t2_update_coupons_get_by_id_lambda.sh)

4. Update and redeploy coupons_update (scripts/t2_update_coupons_update_lambda.sh)

Assessment Part 3 - Secure the Application Program Interface
Commands used to implement token issuing/validation

Design notes:
- bcryptjs (pure-JS bcrypt implementation, same $2a$ hash format, no native
  build step) is used instead of the native `bcrypt` package to avoid a
  Windows node-gyp/Visual Studio build dependency. It reads/writes the same
  hash format as the seeded users table from t0 (bcrypt, 12 rounds).
- Token is a real HS256 JWT (via `jsonwebtoken`), signed with the secret
  0HXc4w5NEzA61HkV, 3600s (1hr) expiry - matches the sample response's
  {token, expiresIn} shape and the 3-part JWT structure.
- coupons_to_secure expects the token in an `Authorization: Bearer <token>`
  header (standard REST convention; not specified explicitly in the
  instructions, so this is the assumption made).

1. Update and redeploy coupons_get_token (scripts/t3_update_coupons_get_token_lambda.sh)
--------------------------------------------------------------------------------------------
npm install --prefix ./lambda/coupons_get_token
cd ./lambda/coupons_get_token && zip -r ../../coupons_get_token.zip . && cd ../..
awslocal lambda update-function-code --function-name coupons_get_token --zip-file fileb://coupons_get_token.zip

2. Update and redeploy coupons_to_secure (scripts/t3_update_coupons_to_secure_lambda.sh)
--------------------------------------------------------------------------------------------
npm install --prefix ./lambda/coupons_to_secure
cd ./lambda/coupons_to_secure && zip -r ../../coupons_to_secure.zip . && cd ../..
awslocal lambda update-function-code --function-name coupons_to_secure --zip-file fileb://coupons_to_secure.zip

3. Verify POST /token (routed by t0's existing API Gateway wiring)

Assessment Part 4 - Implement a File Management Solution
Commands used to provision the S3 bucket/policy and both Lambdas

NOTE on scope discovery: the actual Aurora-authored instruction PDF only
describes the coupons S3 bucket, its deletion policy, and
coupons_import_presigned_url - it never mentions coupons_import. The D2L
rubric later revealed a graded criterion for it ("Handle object upload to
the bucket," 3/9 points), and a separate stale 2023-dated Content-area page
(different author, unrelated to this term) gave concrete detail on what
both Lambdas should actually do:
- coupons_import: write the received coupon (matching
  samples/t4_sample_coupon_import_event.json's shape) as a JSON file in the
  bucket, named "<coupon_id>.json"
- coupons_import_presigned_url: sign the URL for whatever filename is
  passed in the request body's "filename" field (matching
  samples/t4_sample_coupon_import_presigned_url_event.json), not a fixed
  name
Initially implemented coupons_import against DynamoDB and
coupons_import_presigned_url against a fixed "coupon.json" (following the
Aurora PDF's example filename literally). Corrected both once the sample
event files and the stale content's detail were reconciled - see
course-info.md for the full reasoning.

1. Create the coupons S3 bucket (scripts/t4_create_s3_bucket.sh)
---------------------------------------------------------------------
awslocal s3api create-bucket --bucket coupons --acl private --region us-east-1

2. Add the deny-delete-without-MFA bucket policy (scripts/t4_add_bucket_policy.sh)
---------------------------------------------------------------------------------------
awslocal s3api put-bucket-policy --bucket coupons --policy file://scripts/coupons_bucket_policy.json

(Policy: Deny s3:DeleteObject/DeleteObjectVersion/DeleteBucket when the
"Null": {"aws:MultiFactorAuthPresent": "true"} condition matches - i.e. when
there's no MFA-authenticated STS session present. This is AWS's own
documented pattern for "require MFA to delete" via bucket policy.
KNOWN LIMITATION: verified LocalStack (community edition used here) accepts
and stores this policy correctly (see get-bucket-policy output below) but
does NOT actually enforce the Deny condition on delete calls - a test
`aws s3api delete-object` without MFA succeeded despite the policy. This
is a LocalStack enforcement gap, not a defect in the policy itself; the
policy is syntactically and semantically correct for real AWS.)

3. Update and redeploy coupons_import (scripts/t4_update_coupons_import_lambda.sh)
------------------------------------------------------------------------------------------
npm install --prefix ./lambda/coupons_import
cd ./lambda/coupons_import && zip -r ../../coupons_import.zip . && cd ../..
awslocal lambda update-function-code --function-name coupons_import --zip-file fileb://coupons_import.zip

(Writes the received coupon to S3 as "<coupon_id>.json", not DynamoDB.
Needs s3ForcePathStyle: true in the S3 client config - without it the SDK
defaults to virtual-hosted-style addressing (bucket-name.host), which
LocalStack's internal docker IP can't resolve. Hit this exact failure
first: "Inaccessible host: coupons.172.17.0.2" - fixed by adding the
path-style option, same as coupons_import_presigned_url already had.)

4. Update and redeploy coupons_import_presigned_url (scripts/t4_update_coupons_import_presigned_url_lambda.sh)
------------------------------------------------------------------------------------------------------------------
npm install --prefix ./lambda/coupons_import_presigned_url
cd ./lambda/coupons_import_presigned_url && zip -r ../../coupons_import_presigned_url.zip . && cd ../..
awslocal lambda update-function-code --function-name coupons_import_presigned_url --zip-file fileb://coupons_import_presigned_url.zip

(Signs the URL against `http://localhost:4566` rather than
LOCALSTACK_HOSTNAME - the latter only resolves inside the LocalStack docker
network, but a presigned URL is meant to be used by an external client, so
it needs a host that client can actually reach. Object key now comes from
the request body's "filename" field rather than a fixed name.)

5. Verify both endpoints (routed by t0's existing API Gateway wiring)
------------------------------------------------------------------------------
curl -X POST http://<api id>.execute-api.localhost.localstack.cloud:4566/local/coupons/import \
  -H "Content-Type: application/json" --data-raw '{"coupon_id":"...","title":"...", ...}'
=> {"status":"success"}
awslocal s3api get-object --bucket coupons --key <coupon_id>.json downloaded.json
=> the exact coupon JSON that was POSTed

curl -X POST http://<api id>.execute-api.localhost.localstack.cloud:4566/local/coupons/import_presigned_url \
  -H "Content-Type: application/json" --data-raw '{"filename":"some-name.json"}'
=> {"url":"http://localhost:4566/coupons/some-name.json?AWSAccessKeyId=...&Signature=..."}

curl -X PUT "<url from above>" -H "Content-Type: application/json" --data-raw '{"anything":"..."}'
=> HTTP 200 (object uploaded under the requested filename)

6. Run unit tests
--------------------
cd lambda/coupons_import && npx jest
=> PASS - 3/3 (stores the coupon as <coupon_id>.json, 400 missing coupon_id, 400 invalid JSON)
cd lambda/coupons_import_presigned_url && npx jest
=> PASS - 3/3 (signs a URL for the requested filename, 400 missing filename, 400 invalid JSON)

Assessment Part 5 - Implement Asynchronous Communication and Data Processing
Commands used to provision the Kinesis stream/SNS topic and update both Lambdas

(The IAM permissions for Kinesis (stream/coupons) and SNS (topic coupons)
were already granted to coupons_production_role by t0's
coupons_production_policy.json, so no new IAM work was needed here.)

1. Create the coupons Kinesis stream (scripts/t5_create_coupons_stream.sh)
---------------------------------------------------------------------------
awslocal kinesis create-stream --stream-name coupons --shard-count 5

2. Create the coupons SNS topic and a demo HTTP subscription (scripts/t5_create_coupons_topic.sh)
--------------------------------------------------------------------------------------------------------
awslocal sns create-topic --name coupons
awslocal sns subscribe --topic-arn arn:aws:sns:us-east-1:000000000000:coupons \
  --protocol http --notification-endpoint http://localhost:4566/_sns_demo_subscriber

(RESOLVED rubric-vs-PDF question: the PDF wants the topic locked to
email-only; the rubric's competent-level steps for this criterion want an
HTTP subscription added, with the mastery bonus being "restrictions were
created for the subscription type" - i.e. the deny-non-email policy IS the
mastery bonus, not something that should coexist with new HTTP subscriptions
going forward. A Deny-Subscribe policy only blocks *future* Subscribe calls,
it doesn't retroactively remove existing ones - so adding the HTTP
subscription here, BEFORE the policy below is applied, satisfies both
sources: the subscription demonstrates competent-level pub/sub, and the
policy applied after it satisfies the PDF's requirement and the rubric's
mastery bonus, without contradiction. Verified: the HTTP subscription is
still listed after the policy is applied - see step 3 below.)

3. Add the deny-non-email-protocol topic policy (scripts/t5_add_policy_to_coupons_topic.sh)
------------------------------------------------------------------------------------------------
awslocal sns set-topic-attributes --topic-arn arn:aws:sns:us-east-1:000000000000:coupons \
  --attribute-name Policy --attribute-value file://scripts/coupons_topic_policy.json

(Policy: Deny SNS:Subscribe when "StringNotEquals": {"sns:Protocol": "email"}
- i.e. only email-protocol subscriptions are allowed going forward.

Verified the pre-existing HTTP subscription survives:
awslocal sns list-subscriptions-by-topic --topic-arn arn:aws:sns:us-east-1:000000000000:coupons
=> still shows the http subscription from step 2 - see topic_subscription_output.json

KNOWN LIMITATION (same as Part 4's bucket policy): verified LocalStack
accepts and stores this policy correctly (see topic_attributes_output.json)
but does NOT enforce it against *new* subscribe attempts either -
`aws sns subscribe --protocol sms` still succeeded after the policy was
applied (tested, then unsubscribed to clean up). This is a LocalStack
enforcement gap, not a defect in the policy; it is syntactically/
semantically correct for real AWS.)

4. Update and redeploy coupons_event_publisher (scripts/t5_update_coupons_event_publisher_lambda.sh)
-----------------------------------------------------------------------------------------------------------
npm install --prefix ./lambda/coupons_event_publisher
cd ./lambda/coupons_event_publisher && zip -r ../../coupons_event_publisher.zip . && cd ../..
awslocal lambda update-function-code --function-name coupons_event_publisher --zip-file fileb://coupons_event_publisher.zip

5. Update and redeploy coupons_notification_sender (scripts/t5_update_coupons_notification_sender_lambda.sh)
---------------------------------------------------------------------------------------------------------------
npm install --prefix ./lambda/coupons_notification_sender
cd ./lambda/coupons_notification_sender && zip -r ../../coupons_notification_sender.zip . && cd ../..
awslocal lambda update-function-code --function-name coupons_notification_sender --zip-file fileb://coupons_notification_sender.zip

6. Verify event publishing (routed by t0's existing API Gateway wiring)
-----------------------------------------------------------------------------
curl -X POST http://<api id>.execute-api.localhost.localstack.cloud:4566/local/coupons/event_publisher \
  -H "Content-Type: application/json" --data-raw '{"coupon_id":"...","title":"..."}'
=> {"status":"success"}

# read back the record to confirm it actually landed on the stream
# (partition-key hashing means it can be on any of the 5 shards)
for shard in $(awslocal kinesis describe-stream --stream-name coupons --query 'StreamDescription.Shards[].ShardId' --output text); do
  it=$(awslocal kinesis get-shard-iterator --stream-name coupons --shard-id $shard --shard-iterator-type TRIM_HORIZON --query ShardIterator --output text)
  awslocal kinesis get-records --shard-iterator $it --query 'Records[].Data' --output text
done
=> found the exact JSON payload (base64-decoded) on shardId-000000000004

7. Verify notification sending
------------------------------------
curl -X POST http://<api id>.execute-api.localhost.localstack.cloud:4566/local/coupons/notification_sender \
  -H "Content-Type: application/json" --data-raw '{"coupon_id":"...","message":"anything - ignored"}'
=> {"status":"success"} (SNS publish uses the fixed message "A new coupon is available"
   regardless of what's in the request body's "message" field, per the instructions'
