## How to work on this

All the real work happens in `enterprise-cloud-developer-base/`. Setup:

1. Start Docker Desktop, then start LocalStack:
   ```
   localstack start -d
   ```
   (On Windows, `PYTHONUTF8=1` and `PYTHONIOENCODING=utf-8` avoid a console
   encoding crash on startup. LocalStack now requires a free account/auth
   token — run `localstack auth set-token <token>` once if not already set.)
2. From the repo root, bootstrap the shared environment (creates the shared
   IAM role/policy, DynamoDB `users` table, and 8 of the 9 Lambda functions +
   the `coupons` API Gateway):
   ```
   bash scripts/t0_bootstrap_environment.sh
   ```
3. Each project's own `tN_*.sh` scripts (e.g. `t1_provision_coupons_lambda_role.sh`,
   `t1_provision_coupons_list_lambda.sh`, `t1_provision_coupons_endpoint.sh`)
   provision that project's specific role/Lambda/endpoint on top of the `t0`
   baseline — run in the numbered order within each project.
4. Use `awslocal` (not `aws`) for every AWS CLI call — it's a thin wrapper
   that points at LocalStack instead of real AWS.
5. Per-Lambda unit tests live in `lambda/<name>/tests/`, run with
   `npx jest` from that Lambda's folder (needs `npm install` first).
6. End-to-end API tests go in `newman_tests/coupons_newman.json`
   (Postman v2.1 collection), run with:
   ```
   newman run newman_tests/coupons_newman.json --env-var "api_url=<your API's base URL>"
   ```
7. Zip files (`*.zip`) and `node_modules/` are build artifacts left behind
   by the provisioning scripts — gitignored, regenerated by the scripts
   themselves, never need to be committed.

Each project's `instructions/Part N instruction.pdf` (downloaded from D2L,
gitignored — never push these) is the authoritative spec; don't infer scope
from the repo's sample files or rubric text alone (see the Project 1 note
below for why that matters).
